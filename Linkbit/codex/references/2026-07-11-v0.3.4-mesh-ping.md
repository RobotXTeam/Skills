# v0.3.4 Mesh Ping Diagnosis

## Scope

This note records the `v0.3.3` mesh ping failure reproduced on 2026-07-11 and the `v0.3.4` correction.

## Reproduced state

- The source and target were online and present in the source device's `network-config`.
- `LINKBIT_MESH_ALL_DEVICES=true` exposed every target without explicit policies.
- The source had a `10.88.0.0/16` route through `linkbit0` and a Hub peer.
- `wg show linkbit0` reported outbound bytes but `0 B received` from the Hub.
- Hub virtual-IP ICMP had 100% loss.
- `linkbit ping <target>` failed because `v0.3.3` invoked the operating-system `ping` command only.
- `linkbit speed <target>` succeeded through TCP Relay, proving that device authentication, Mesh authorization, Relay streaming, and the target Agent were healthy.

## Root causes

1. The CLI treated WireGuard ICMP as the only Linkbit ping transport even though Linkbit already supported Relay fallback for service traffic and speed probes.
2. A long-running Agent fetched `network-config` only at startup, so later device, key, endpoint, or Hub changes were not applied until restart.
3. The observed Hub endpoint returned no WireGuard packets. This is a deployment/UDP-path issue, separate from Mesh authorization.

## v0.3.4 behavior

- `linkbit ping` tries direct ICMP briefly and falls back to three zero-payload authenticated Relay probes.
- Text and JSON output identify the path as `direct` or `relay`.
- The fallback reuses the `speed` probe protocol, so a `v0.3.4` CLI can probe targets still running a compatible `v0.3.3` Agent.
- The Agent refreshes network config periodically and only reapplies WireGuard when the virtual IP, peer identity, endpoint, or allowed IPs change. Status timestamps and peer order do not rebuild the interface.

## Verification

```sh
linkbit trace <target>
linkbit ping <target>
linkbit --json ping <target>
linkbit speed <target>
sudo wg show linkbit0
```

Treat `via relay` as a valid Linkbit device reachability result. To require native ICMP, also require a recent WireGuard handshake, received bytes greater than zero, Hub IP ping success, and `ping <target-virtual-ip>` success.
